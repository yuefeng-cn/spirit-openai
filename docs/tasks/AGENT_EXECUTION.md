# Agent 执行约定

本文件约束后续编码 Agent 如何执行 `docs/tasks/` 中的任务。目标是让不同 Agent 能按同一边界接力，而不是自行扩展方案。

## 1. 指令优先级

从高到低：

1. 仓库根目录 `AGENTS.md`；
2. 用户当前明确要求；
3. 当前任务 ID 所在的任务文档；
4. `IMAGE_AGENT_MVP_PLAN.md`；
5. 既有代码风格与测试。

任务文档与计划书有冲突时，以当前任务文档的更具体约束为准；不能自行修改任务目标来规避验收。

## 2. 单任务边界

- 一次只实现用户指定的一个任务 ID，例如 `P2-02`；
- 只修改完成该任务必需的文件和测试；不顺带实现后续任务；
- 不新增计划外的表、目录、命令、抽象层或 Provider；
- 不改变已定义的会话隔离、`@img-N` 引用、OSS 权威存储和图片二进制不入库等核心约束；
- 不执行 `git commit`、`git push`、`git pull` 或 `git merge`。

## 3. 开始前必读内容

执行任务前按以下顺序阅读：

1. 根目录 `AGENTS.md`；
2. `docs/tasks/README.md`；
3. 当前任务所在文档的完整内容；
4. 当前任务直接依赖的前置任务文档；
5. `IMAGE_AGENT_MVP_PLAN.md` 中对应章节；
6. 与本任务直接相关的现有源文件和测试文件。

如仓库存在 `.codegraph/`，先按 `AGENTS.md` 使用 CodeGraph；不存在则不使用。

## 4. 实施流程

1. 确认当前任务 ID、前置任务是否已完成，以及现有测试基线；
2. 先补充或调整该任务要求的测试，再实现最小代码；
3. 保持模块边界：Provider 只在 `src/image/providers/`，图片业务集中在 `src/image/`；
4. 运行任务文档列出的验收命令；涉及已有功能时额外运行受影响的测试；
5. 检查未跟踪或修改文件，确认没有图片、密钥、Base64、签名 URL 或本机输出文件进入仓库。

注释和面向用户的输出使用中文。

## 5. 关键实现规则

- 所有会话、消息和图片查询都必须带 `conversationId` 限制；
- 调用图片 Provider 前，必须把用户指代解析为唯一 `targetImageVersionId`；不允许把“这张图”“上一张”等代词原样传入；
- 图片文件的权威来源是 OSS；PostgreSQL 只保存元数据和 `objectKey`；
- CLI 展示的本机文件是可重新物化副本，路径由配置和图片元数据推导，不写入数据库；
- Mock Provider 必须离线、可重复；真实 Provider 仅在 P5 实现；
- Provider 连续状态仅是辅助。状态缺失、过期或不兼容时，必须可以从 OSS 读取目标图重新编辑。

## 6. 未定义或冲突时的处理

- 先在现有计划、任务和代码中寻找最小且一致的解释；
- 若不影响外部接口且可由既有约束唯一推导，可采用最小实现并在最终说明中写明；
- 若涉及新的用户命令、数据库表、跨模块接口、Provider 行为或任务范围，停止扩展并向用户说明待确认项；
- 不以“未来可能需要”为理由提前抽象。

## 7. 完成时的固定汇报格式

完成一个任务后，使用以下格式汇报：

```text
任务：P?-??
状态：完成 / 未完成

修改：
- <文件路径>：<一句话说明>

验证：
- <命令>：通过 / 未通过

未完成或待确认：
- 无 / <具体事项>
```

不要声称未实际运行的验证已通过。
